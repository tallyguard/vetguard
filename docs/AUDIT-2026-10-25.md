## Findings

Severity, evidence, and the fix at the right layer. "Repro" means executed
against the built CLI this session; "independent" means reproduced by the
blind reviewer as well.

### H1 (HIGH, hostile input, stop-the-line)

Hostile dependency name hangs or OOMs the scanner. `edits1`
(src/util/names.ts:37) via `findNearMiss` (src/ecosystems/npm/popular.ts:137,
no length cap) via unvalidated names (src/ecosystems/npm/lockfile.ts:111,
src/ecosystems/npm/manifest.ts:73). Repro (independent): a 100 KB name in a
hostile package.json crashes `node dist/cli.js scan --offline` in 3.4 s with
`Reached heap limit` (exit 134); 5 K chars takes 2.8 s; 20 K exceeds 120 s.
`--offline` does not help. SECURITY.md declares this class in scope. Fix:
validate name shape and length (npm: max 214 chars, small charset) at the
collectors and `spec.ts`, thread rejects as unverifiable facts; guard length
in `findNearMiss`.

### H2 (HIGH, dev pipeline)

Corpus refresh executes fetched third-party JavaScript.
scripts/refresh-popular.mjs:22-24 fetches `top-download.js` from jsdelivr and
runs `import("data:text/javascript;base64," + ...)`; monthly,
refresh-corpus.yml runs it with `contents: write`. The version pin is
`latest`, so a compromised `npm-high-impact` release or CDN executes in a
token-holding workflow with no lockfile, no integrity check, no human review.
Fix: lockfile-pinned devDependency or text parsing; never import fetched
bytes.

### M1 (MEDIUM, output integrity)

Terminal escape injection. src/output/terminal.ts:51-59 renders packageName,
location, and the unverified list with no control-character stripping.
Repro (independent): raw ESC bytes pass through; a hostile name forges green
bold `Verdict: clean` text inside the findings line and can set the terminal
title. Fix: one shared control-char stripper for every hostile-derived string
in renderTerminal.

### M2 (MEDIUM, output integrity)

Markdown link/image injection into the trusted PR bot comment.
src/output/markdown.ts:22-29 `cell()` does not escape `[` `]` `!`. Repro
(independent): a dependency name renders as a clickable link plus a tracking
image in the github-actions[bot] comment. Fix: escape brackets and leading
`!`, or render names in code spans.

### M3 (MEDIUM, verdict honesty)

git/github-sourced dependencies scan `clean` with zero checks.
src/ecosystems/npm/enrich.ts:52-57 returns git/file/link/workspace/alias
sources untouched; manifest.ts:23-30 routes `github:evil/repo` and bare
`evil/repo` to git. A manifest of github deps yields verdict clean
(engine.ts:68-72). No DECISIONS entry records the exemption. Decision
(2026-10-25, maintainer): git and alias route to unverified; file, link, and
workspace stay local-only with a dated DECISIONS entry. Fix lands in
enrich.ts plus DECISIONS.md.

### M4 (MEDIUM, fact integrity)

Registry/OSV in-run cache keys collide. registry.ts:132, osv.ts:70-72 key on
`name@version` strings; a hostile lockfile name containing `@` aliases one
fact's lookup onto another's. Repro (independent): a version-less lookup
inherited `requestedVersionPublished` from a colliding versioned one. Fix:
key on `JSON.stringify([name, version])`.

### M5 (MEDIUM, fact integrity)

`version in versions` counts inherited keys as published (registry.ts:84).
Repro (independent): pinned version `"toString"` yields
`requestedVersionPublished: true` (prototype chain). Detector-level only;
verdict still degrades via isExactVersion. Fix: `Object.hasOwn`.

### M6 (MEDIUM, verdict honesty)

Malformed lockfile entries silently dropped. lockfile.ts:113-116 skips
non-object entries, non-string versions, and empty names with no record.
Repro: a lockfile whose entries are all malformed scans to
`0 package(s) ... Verdict: clean`. Related: lockfile.ts:82 returns `absent`
for read errors (EACCES), silently swapping to manifest basis with no
warning (repro'd). Fix: thread skipped entries as unverifiable facts;
distinguish unreadable from absent.

### Low

- L1: chunked network bodies without Content-Length are not byte-capped
  (util/fs.ts:35-43, self-documented). Stream-count into the 64 MB cap.
- L2: names interpolated into URLs unencoded or partially encoded
  (downloads.ts:42, registry.ts:43). encodeURIComponent.
- L3: empty package name fetches the registry root and reports found
  (registry.ts:105, spec.ts accepts empty). Reject invalid names.
- L4: third-party actions float major tags; release.yml:27 runs
  `npm install -g npm@latest` unpinned. SHA-pin; pin the npm major.
- L5: .gitignore lacks `docs/private/` (CLAUDE.md section 5 calls it
  gitignored) and `.npmrc`.
- L6: PROJECT-STATE stale bits (6/6 positives vs current 7/7, last verified
  2026-07-22); "unlock" in DECISIONS.md and ROADMAP.md (binding catalog,
  AI-ANTIPATTERNS.md:212).
- L7 (info): stat-then-read race in readTextCapped; could-not-verify exits 0
  (documented choice); no dependency-count cap before the 128 MB lockfile
  cap; failed lookups memoized for the whole run (honest but sticky); ci.yml
  runs `npm ci` on PR-controlled manifests (standard PR-CI tradeoff, consider
  --ignore-scripts).
